Bound And Drain Queue
src/queue.js:1-13
importantNot viewed
enqueue now defaults to a limit of 100 and, when the queue is at or above that limit, discards exactly one oldest element before appending. This changes existing callers from unbounded retention to silent eviction. It maintains the limit when the queue starts within bounds and the limit is positive, but an already-oversized queue remains oversized because only one element is shifted; zero, negative, fractional, and otherwise invalid limits are not validated. drain removes each item before invoking a synchronous handler, preserving FIFO order. If the handler throws, that item is already lost while later items remain; if the handler appends to the same queue, the loop also consumes those additions and may not terminate. Whether those lifecycle semantics are intended cannot be determined from this repository.

Retry Action Attempts
src/retry.js:1-11
importantNot viewed
retry invokes and awaits action up to attempts times, returning the first successful result and otherwise rethrowing the final caught value; both synchronous throws and promise rejections are retried. Attempts run immediately with no delay or cancellation hook, and all failures are treated as retryable. A non-positive, NaN, or otherwise loop-preventing attempts value reaches throw last without calling action, which throws undefined; fractional positive values effectively round up through the loop condition. There is no repository evidence establishing whether callers validate this input or need backoff/selective retry semantics.
